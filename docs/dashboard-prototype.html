预填充画面（新：实时速度和进度）

预计超过 3 秒的预填充一开始就切到这个画面；3 秒内的短预填充只有状态条和流指示点变化。引擎按 2048 个 token 一块来算，所以速度大约每 0.9 秒跳一次。

vLLM 读不到预填充进度：提示长度和缓存命中是准数，主数字是最近几次请求的平均速度（标“近期平均”，本次预填充期间不变），进度条按时间匀速前进（“已算约”）。新请求要等引擎算完第一步才看得到，这个画面会晚 2–5 秒出现，“已等待”从估计的起点算。

设计说明
  • 显示的是整台机器：最多 5 条流同时跑，所有数字要么是所有流的合计，要么是这一轮的累计。
  • 流指示点：状态条最左边 5 个点，从左到右是解码中（绿）、预填充中（琥珀）、空着（灰）；有排队时后面写“+2”。
  • 状态：有任何一条流在解码就是“解码中”；没有解码、有预填充才是“预填充中”；全部结束才是“完成”。
  • 解码：仪表盘是所有流的合计速度（最近 2.5 秒平均）。刻度 0 / 25 / 50 / 100 / 200 / 300，前密后疏。多条流时状态条写“解码 n · 预填充 n · 排队 n”。
  • 预填充（新）：仪表盘是实时预填充速度（琥珀色，刻度 0–3K），下面是进度条“已算 / 提示”。单个请求时右侧是“缓存命中 / 已等待 / 内存”；一轮模式下右侧不变，已用时、缓存命中、剩余时间写在状态条。
  • 一轮：上一个请求结束后 60 秒内来的请求算同一轮；并发的请求一定在同一轮。本轮请求 ≥ 2 时右侧固定为“本轮请求 / 累计输出 / 本轮平均”。本轮没出现过并发时平均值是引擎给的精确值（带“精确”）；出现过并发时改为“本轮输出 ÷ 有流在解码的时长”，和仪表盘的合计速度一致。
  • 完成：所有流都结束才出现，停 4 秒。单个请求显示引擎的精确成绩；一轮模式显示本轮统计（灰色）。
  • 空闲 = 今日统计（新）：今日费用（按 API 价格折算：输入 $0.15、缓存命中 $0.016、输出 $0.47，每百万 token）、今日输入、输出、请求数。按太平洋时间 0 点清零。一轮中间的空隙不切到今日统计，一轮结束后才切。
  • 上下文条：显示占用最大的那条流。占到 80% 变琥珀色、95% 变红色。
  • 外挂失效：预填充画面退回“已用时”，其他不受影响；今日统计的状态条会标“外挂未生效”。
  • 两种引擎（新）：空闲和离线时模型名后面标出当前引擎（TensorFold 标了“外挂未生效”时不再重复写引擎名）。vLLM 没有外挂：预填充画面的速度和进度是估算的；流指示点从 4 个起，同时在跑的流多了再加；长预填充期间其他流几乎不出字，仪表盘会如实掉到个位数。
  • 没有模拟的：空闲 30 分钟后画面调暗到 40%。
